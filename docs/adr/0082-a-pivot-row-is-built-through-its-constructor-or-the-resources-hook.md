# A pivot row is built through its constructor, or the resource's hook

The persister skipped the constructor of a new pivot row, so an id or a collection the constructor set was missing and the insert failed. It now calls a constructor that takes no argument, as it already did for link rows, and otherwise asks the resource that declares the relation, through `InstantiatesPivotInterface`, before building the row the way Doctrine hydrates one. The hook sits on the resource rather than on the relation because the bundle's other build and delete hooks (`InstantiatesEntityInterface`, `DeletesEntityInterface`) live there and get the same `HookContext`, and because the pivot entity is a Doctrine fact core's storage-agnostic relation shouldn't carry. A resource's own entity keeps its documented constructor-less create, since that hook already exists for it and calling its constructor by default would change what every create does.

# A singleton resolves its id before the operation is built

A singleton type is routed at `/{uriType}` with no `{id}`, and the request listener, the action path and the Atomic Operations executor each resolve the caller's id through the type's `resolveSingletonId()` before they build the operation, passing the Symfony user and the HttpFoundation request as context attributes. Every later step then sees an ordinary fetch, update, relationship or action on a real id, so data providers, Doctrine extensions, security expressions, hooks, transactions and the `409` id check need no singleton branch, and the type's access scope is the one place that keeps a caller to their own row. The declaration stays on the classes core registers rather than a `#[AsJsonApiResource]` flag, because core's links and OpenAPI projection read it from there and a bundle-only flag would leave them at `/{uriType}/{id}`.

# Operation example overrides are declared on the attributes and the export reports the gaps

Core builds a worked example for every operation from declared field examples (core ADR 0176), so the bundle passes its overrides through the attributes that already describe each type and action: `operationExamples` on `#[AsJsonApiResource]` and `#[AsJsonApiSerializer]`, keyed by core's operation names rather than the bundle's `Operation` case names because relation operations have no case, and `example` on `#[AsJsonApiAction]`. They ride the compiled container as JSON, like the other nested attribute values, since the container cannot dump core's `OperationExample`. Generation is a document-wide `json_api.openapi.examples` switch with a per-server `openapi_examples` override, shaped like `reject_read_only_attributes`. The export command prints each missing example on stderr and fails under `--strict`, but the served document and the warmer stay silent, because a gap in an example is an authoring problem for CI to catch rather than something to log on every warmup.

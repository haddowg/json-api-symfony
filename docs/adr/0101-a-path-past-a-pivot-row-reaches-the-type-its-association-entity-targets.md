# A path past a pivot row reaches the type its association entity targets

A `->through()` path can go on from a pivot row, as in `pivot.addedBy`, but a pivot row has no type, so core asks the provider which type each of its relations reaches. The Doctrine provider answers from the association entity's mapping, the entity the pivot-row filters already walk, and names the one registered type whose entity the association targets, refusing at warm-up when none or several do, because the reached type's scope, read gate and encoder have to apply and a guess would apply the wrong ones. The association entity's associations back to the parent and to the member are the exception: the relation already names their types. A leading `pivot` runs only where the relation's pivot query has joined the row, as the `pivot.` column filters do, while a mid-path `pivot` joins the association entity inside the filter's `EXISTS` with the member it links scoped like any other hop.

# Id encoding is resolved per server

The `IdEncoderResolver` took a type's `Id` field from the first resource class anywhere that declared the type, so when two servers served a type through classes with different encoders, route patterns or client-id policies, one server routed, decoded and documented ids with the other's field, and returned 404 for rows that exist. It now resolves the class the server serves the type with. The route loader and the OpenAPI projection name their server. The Doctrine provider, persister and windowed batch have no server in their signatures, so the handler binds each operation's server on the resolver and those lookups use it: the request's `_jsonapi_server`, else the server the operation's context was built for, else `default`. Before any operation binds a server the default server answers, and when the bound server doesn't serve the type the first class that declares it anywhere answers, which is what every lookup did before. The in-memory provider and persister decode no ids, so only the routing, client-id policy and OpenAPI id pattern change for them.

# Auth failures defer to the firewall's entry point, then render as JSON:API

Answering every JSON:API error at priority 128 meant Symfony Security's listener at priority 1 never ran for an authentication failure, so the firewall's entry point never added its `WWW-Authenticate` challenge, which RFC 9110 requires on a `401` and which OAuth and MCP clients use for discovery. So when the request's firewall has an entry point, the listener now leaves an `AuthenticationException` or an unauthenticated access denial to the firewall, gives an entry point's `401` the JSON:API `AUTHENTICATION_REQUIRED` body while keeping its headers, and renders anything the firewall leaves behind at priority -64, still ahead of Symfony's error page, so ADR 0003 holds. An entry point that answers with another status, such as a login redirect, keeps its response, and an authenticated denial still renders as a `403` at 128.

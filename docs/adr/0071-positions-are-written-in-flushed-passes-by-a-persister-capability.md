# Positions are written in flushed passes by a persister capability

A positioned relation's positions are written by the persister that changes its members, because only the store knows its rows and how to keep a unique owner and position key intact. A `MorphToMany` declared with `identifiedByRows()` takes them from core's `LinkRowWritePlan` through `WritesLinkRowsInterface`, its inserts carrying final positions, so its position column can be `NOT NULL`. Every other positioned relation goes through `WritesPositionsInterface`, where Doctrine applies core's position plan as flushes inside the write's transaction and writes a row the write adds at a temporary position in the first, since the membership change has already queued it and a unit of work can't hold an insert back to the last flush. The handler resolves the stored column, which only the server can see for a field of the related type. A positioned `hasMany` accepts `sort` by its position field, and the document lists it, so the order it reads in is one a client can name.

# A cursor page selects a sort expression, and a cursor sort is checked at warm-up

DQL accepts `IS NULL` and an `ORDER BY` term after little more than a field path or a function call, and refuses an identification variable declared twice, so a custom sort's subquery, `CASE` or `COALESCE` failed on a cursor page. The keyset now selects any expression other than a path `AS HIDDEN` with its null flag, orders by those result variables and tests for null by comparing the expression with itself. An expression that declares its own variables is rebuilt with a suffix for each place the keyset writes it, and one whose value PHP can't compute from the entity is selected visibly so the cursor reads the boundary row's value from the query. A collection that may page by cursor has its declared sorts checked at warm-up, so a sort that can't key the page fails the build instead of answering every request with a 500; a sort family still resolves per request, so it is checked then.

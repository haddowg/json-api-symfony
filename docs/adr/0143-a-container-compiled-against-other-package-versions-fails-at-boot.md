# A container compiled against other package versions fails at boot

Symfony checks a non-debug container for freshness only when it first builds it, so after an upgrade a cached test or production container keeps running the old service wiring, and an app's tests can pass against behaviour the installed code no longer has. The bundle records the installed versions of itself and of haddowg/json-api from `Composer\InstalledVersions` as a container parameter at compile, and `JsonApiBundle::boot()` compares them with the installed ones and throws a `LogicException` telling the user to clear that environment's cache. The pretty version is always compared, and the reference only when both sides know it and the version is a release: a `dev-` or `-dev` version, as a path repository or a branch install has, moves its reference while the container stays valid, so comparing it would raise false alarms during development. A container that recorded nothing was compiled before this check and counts as stale; nothing is checked when `InstalledVersions` is unavailable, or while `cache:clear` boots the stale container to replace it.

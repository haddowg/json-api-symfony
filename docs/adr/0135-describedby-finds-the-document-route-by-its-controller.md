# describedby finds the document route by its controller

An app that routes `OpenApiController` itself, under its own route names, used to lose every `describedby` without a sign, because the document URL was generated from the bundle's route names only. When those names aren't registered the bundle now looks for a route whose `_controller` is `OpenApiController` and whose `server` route attribute picks the server, scanning the route collection once at cache warmup (or once per process without a warmed result) because the scan is too costly per request. When no route serves a server's document while the expose gate is open and no `document_url` is set, the warmup logs a warning rather than failing, since `describedby` is optional and a closed gate is the documented way to have none.

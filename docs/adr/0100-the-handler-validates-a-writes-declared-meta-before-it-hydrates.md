# The handler validates a write's declared meta before it hydrates

Core lets a type declare a write's top-level meta and its resource objects' meta, and closes every declared meta object. The handler validates each write's meta through the same Validator bridge pass attributes take, so a member is refused, typed and normalized exactly as an attribute is, and puts the typed values on the request as core's WrittenMeta, so the hydrator, the lifecycle events, the hook context and an action's context read one source. Debug mode alone checks rendered resource objects and linkage identifiers against their declarations, in the view listener and for each atomic result, and warm-up refuses a misdeclaration and a getMeta() override beside resourceMeta(), since the declaration covers the object getMeta() would add to. A delete's meta is validated by a BeforeDeleteEvent listener below the security gate and above the hook listeners, since the gate and the hooks share that event, so a refused caller gets its 403 first and the hooks still read typed meta.

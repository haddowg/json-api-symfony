# Query extensions take statement-unique aliases

A query extension now runs on the type queried and again inside each subquery that scopes a relation a filter or sort reaches through, so an alias it names itself can be defined twice in one DQL statement, which Doctrine refuses. `ExtensionContext::uniqueAlias()` hands out aliases from one allocator the root query and every subquery the bundle embeds in it share, so the same extension gets a new alias each run, and the alias stays the same from one request to the next for Doctrine's query cache. When Doctrine still reports an alias defined twice, the exception listener replaces it with a `LogicException` naming the extensions applied in the request and pointing at `uniqueAlias()`, since the bare Doctrine message names neither.

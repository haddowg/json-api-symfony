# A pivot whose fields are all computed needs no association entity

A `belongsToMany` is treated as pivot-backed, and so routed through its association entity, only when it declares a stored pivot field; one whose fields are all computed, with no column, is served over its plain join table on Doctrine and over the stored list in memory. The in-memory provider keeps no pivot storage, so there it renders only the computed fields, for an all-computed or a mixed relation alike, and never a stored one. `PivotMetaSerializer` renders every field read through a hook, a computed one or a stored one with `extractUsing()`, from the parent, each member and the member's stored values at render time. Rendering in the serializer rather than in each provider keeps one path for every endpoint and both providers, and a stored field, hooked or not, still reads and writes its association entity so a mixed relation keeps today's query and write behaviour.

# Every relationship write checks its linkage against the related type's provider

Linkage to a resource that does not exist was only refused when its type was scoped or the persister happened to notice: a `fillUsing()` hook or a declared `MorphToMany`'s link rows stored the id as sent, a Doctrine to-one stored a dangling key, an inverse to-many answered `500`, and the in-memory persister cleared or dropped it. Every relationship write now checks each id it names against its type's provider before anything is stored, on create, update, every relationship endpoint mode and Atomic Operations, and refuses one the provider does not serve with `404 RESOURCE_NOT_FOUND`, whether no row holds it or a scope hides it. A remove is checked too, so the two adapters agree, while removing an existing resource that is not a member still changes nothing. One routine does it, asking each type once per write through `FetchesByIdsInterface` or `AdmitsIdsInterface`, and through `fetchOne()` when the provider has neither or for an id the batch left out, which a batch can do for a row it cannot key. The rows a Doctrine batch loads stay in the identity map, so the persister's `getReference()` finds them without another query, and the check costs one `SELECT` per related type. This replaces the last sentence of ADR 0047, which left unscoped types unchecked, and a type no provider serves still has nothing to check against.

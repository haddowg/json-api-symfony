# The bundle registers the Nested Fieldsets profile and narrows on every render path

Core decides which `fields[type]=<attribute>.<key>` members a type accepts and advertises the Nested Fieldsets profile from the response layer, so the bundle adds `NestedFieldsetsProfile` to the default `json_api.profiles` after the three it already registered, keeping the order Laravel's default must match, and otherwise lets its render paths inherit the behaviour: primary data, `included`, related endpoints, write responses and atomic results all render through core's resource and responses with the request's fieldsets. Both providers load the entity whole and trim on render, because Doctrine has no per-key load for a `json` column; a reader that wants to read less does so in an `extractUsing()` hook, which receives the selected keys.

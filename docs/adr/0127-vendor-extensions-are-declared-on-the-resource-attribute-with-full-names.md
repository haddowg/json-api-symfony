# Vendor extensions are declared on the resource attribute, with full names

Core 1.4 lets type metadata declare OpenAPI `x-` extensions through the opt-in `DeclaresOperationExtensions`, so the bundle's `TypeMetadata` implements it and fills it from `#[AsJsonApiResource(extensions:, operationExtensions:)]`, keyed by `Operation` case name like `operationDescriptions`. Core has no resource method hook for extensions, so the attribute is the only declarative site and a computed value goes through the document decorator. Core's withers accept a bare name and add the prefix, but the attribute rejects anything not starting with `x-` (and the reserved `x-oai-`/`x-oas-`) when the container compiles, because on a declaration a missing prefix is more likely a typo than shorthand, and the error is cheaper there than in a published document.

A standalone serializer declares them the same way on `#[AsJsonApiSerializer]`, sharing the attribute validation, and an `operationExtensions` entry for an operation the type doesn't expose (outside its `operations`, or a write on a `readOnly` resource) fails the build like a response override for one does, because it would never reach the document.

# Linkage a write stores unresolved is checked against its type's provider

A `fillUsing()` hook gets bare identifiers and a declared `MorphToMany` writes them onto link rows, so no persister ever looks the targets up, and before this an id no row holds was stored and answered `201` or `200`. Each id such a write names must now be one its type's provider serves, checked before the hook runs or a row is written and refused with the `404` a scoped type's hidden row already raises. The check asks each type once through `AdmitsIdsInterface` or `FetchesByIdsInterface` where the provider offers either, and through `fetchOne()` otherwise or for an id the batch left out. A remove isn't checked, matching every other relation, and a type no provider serves has nothing to check against. Relations the persister writes itself keep relying on the persister, since checking those too would add a query to every plain write.

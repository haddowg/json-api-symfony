# An ambiguous pivot side is named in through() or fails warm-up

An association entity with two `ManyToOne`s to one class, as one linking a type to itself has, gave both sides of the pivot the first association found, so a relation read its parent as its own member. A side named with `through(parent:, related:)` is taken once it is checked to be a `ManyToOne` to the right class; a side left out is the entity's one association to that class, or for the parent side the association the parent's `OneToMany` the relation is stored as is mapped by. Anything still ambiguous on either side fails the cache warm-up, naming the candidates and the `through()` that settles it, because a wrong guess silently swaps the members of both directions; an application that relied on the first association being picked now has to name the side.

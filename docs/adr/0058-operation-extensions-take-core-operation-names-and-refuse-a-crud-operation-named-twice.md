# Operation extensions take core operation names and refuse a CRUD operation named twice

`operationExtensions` could only target the five CRUD operations by `Operation` case name, so a related or relationship endpoint, such as one an MCP server should not offer as a tool, had no extensions of its own. It now also takes core's operation names, the keys `operationExamples` and `operationScopes` already use, and hands those sets to core's `DeclaresNamedOperationExtensions`, which merges them over the case-name sets. Naming one CRUD operation both ways, `Delete` and `delete`, fails the container build rather than letting the higher layer win quietly, because two keys for one operation on one attribute is almost always a mistake and the merge order would be invisible at the declaration.

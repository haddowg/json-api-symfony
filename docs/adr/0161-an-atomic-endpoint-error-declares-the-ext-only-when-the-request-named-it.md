# An atomic endpoint error declares the ext only when the request named it

ADR 0088 declared the atomic `ext` on every error from the `_jsonapi_atomic` route except a `415` or `406`, chosen by exception type, so an error raised before negotiation, such as a `405` for `GET /operations` or a firewall `401`/`403`, claimed the extension for a client that never asked for it. The `ExceptionListener` now declares it only when the request named it, in the `Content-Type` `ext` parameter or in the `ext` of any `Accept` range. It reads the headers through core's `JsonApiRequest` rather than trusting negotiation, which may not have run. The `415`/`406` exclusion stays: a request that failed negotiation over the ext does not get it, even when the other header named it. The Laravel adapter applies the same rule, so both adapters send the same `Content-Type` for the same request.

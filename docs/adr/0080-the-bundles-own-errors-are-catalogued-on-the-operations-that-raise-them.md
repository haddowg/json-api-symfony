# The bundle's own errors are catalogued on the operations that raise them

`VALIDATION_FAILED` and the Atomic Operations codes reached clients without appearing in the OpenAPI error catalogue, so a generated client couldn't name them. Each is now a described error, and every server's metadata catalogues them ahead of the application's: the atomic codes on `POST /operations` alone, and `VALIDATION_FAILED` on the writes that read a document, the batch, and the actions of that server that take a document. The action list needs the server's types, which a descriptor can't see, so the bundle narrows the descriptor's scope per server with a `ScopedErrorSource`. The Laravel package catalogues the same codes in the same order with the same texts, because its documents must match the bundle's byte for byte.

# Naive datetime bounds and writes use the default timezone

Doctrine's `datetime` types drop the offset and read the column back in PHP's default timezone, so a client value in `Z` or another offset compared or stored its own wall-clock time against local times. The filter handler now binds a date-time with the compared column's mapped type, converting it to `date_default_timezone_get()` first for a naive `datetime` column, and the write handler converts the `DateTime` attributes and pivot fields a request sends the same way before hydration. The zone is read each time because applications switch it per request. Only values the client wrote are converted, so a date-time the application sets itself is persisted as given. A `date` column keeps the bound's own day, because converting a midnight bound can move it to the previous day, and cursor keys are left alone because they already carry the stored wall-clock time.

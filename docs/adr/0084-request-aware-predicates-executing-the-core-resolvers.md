# Core's request-aware predicates are enforced at every bundle execution site, and OpenAPI documents the superset

Core lets field visibility and writability, relationship mutability and includability depend on the request, and the bundle is where they execute: validation, hydration, the relationship endpoints, embedded relationship writes, include batching and every read-side batcher ask the per-request resolvers, so validation and hydration never disagree about a field for the same caller and a relation write-only for the caller is left out of every read path. The replace gate on an embedded relationship (`cannotReplace(fn)`) is skipped on create, because a create sets the initial state and a relation with no endpoint of its own could otherwise never be set. OpenAPI generation is request-independent, so the document describes the superset: a sometimes-hidden field or sometimes-prohibited verb still appears.

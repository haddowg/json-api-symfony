# The Doctrine layer converts ids through their mapped type

The provider and persister used to treat an identifier as an int or a string: they bound ids untyped and skipped any id that was not scalar, so a `uuid` id stored as `BINARY(16)` 404'd on lookup, rendered `data: null` for a to-one and broke every batched relation. Ids now go through the identifier field's Doctrine type in one helper: values are keyed and bound in their database form, with the type's binding type and its array form for `IN` lists, and converted to their PHP form before `getReference()`. We chose the mapped type over a bundle-level id codec because the type already knows every form of the id, so an application needs no encoder for a `uuid` key and an existing encoder that decodes to the binary form keeps working.

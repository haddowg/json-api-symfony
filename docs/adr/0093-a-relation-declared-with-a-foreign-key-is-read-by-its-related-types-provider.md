# A relation declared with a foreign key is read by its related type's provider

A to-many on a parent no Doctrine entity maps, such as a singleton a custom provider serves, failed on every read, because the related read scoped by the parent's own mapping and asked Doctrine for the metadata of a class it doesn't map. A relation declared with a foreign key is now always read by the related type's provider through `ReadsByForeignKeyInterface`, handed the page of parents keyed by wire id with the keys their rows hold, so it pushes down one `WHERE <foreign key> IN (:keys)` query under its own scope and windows it per parent, whatever provider serves the parents and whatever the parent model holds. A relation from a type no entity maps into a Doctrine type with no foreign key, no `extractUsing()` and no parent provider batching its reads is refused at warm-up rather than left to fail at request time, and the Doctrine provider refuses such a read without loading metadata for the parent.

# A morph relation is polymorphic at runtime whatever its type count

Core now projects a `MorphTo` or `MorphToMany` over one type as a union with no filter, sort or page parameters from that type (core ADR 0184), while the bundle still decided polymorphism by counting types and so served the related type's vocabulary the document no longer listed. Every decision about what a request may ask of a relation now goes through one rule, polymorphic when it is a core `PolymorphicRelationInterface` or lists several types, and the OpenAPI relation metadata answers `isPolymorphic()` from the same rule, so the document and the endpoints agree. How the members load still goes by the count: one type is one query, so the Doctrine provider keeps serving a single-type `MorphToMany` and only refuses one whose members span entity classes.

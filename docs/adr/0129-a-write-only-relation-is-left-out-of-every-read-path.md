# A write-only relation is left out of every read path

Core stops rendering a `writeOnly()` relation, but the bundle's read-side batchers enumerated relations through `TypeMetadataResolver::relationsFor()`, so a `withData()` write-only to-many was still windowed, pivot-queried and accepted as a `relatedQuery` path. The read paths now enumerate `readableRelationsFor()`, which drops a relation write-only for the current request, so a predicate-gated relation is skipped exactly when core hides it; write paths and the eager loads behind `on()` chains keep the full set. `RelationMetadata` implements core's `DeclaresWriteOnlyRelation` and reports only an unconditional `writeOnly()`, so the OpenAPI document keeps describing a predicate-gated relation as readable, the same superset rule attributes follow.

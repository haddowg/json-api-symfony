# A 405 on a JSON:API path is found by re-matching its allowed methods

The router refuses a method a path does not accept before any route matches, so the route-scoped exception listener saw no marker and a write to a read-only type got Symfony's HTML `405`. Symfony's `MethodNotAllowedHttpException` names only the allowed methods, so the listener asks the router which route each of them reaches on the same path and renders core's `METHOD_NOT_ALLOWED`, with its `Allow` header, when one of those routes carries the marker, using that route's server and mount. We chose this over matching the path against each server's mount prefix because a prefix also covers an application's own routes beneath it, while re-matching answers only for paths a JSON:API route actually serves and costs nothing on a request that does not fail.

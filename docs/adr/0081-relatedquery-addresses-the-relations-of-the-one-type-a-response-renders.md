# relatedQuery addresses the relations of the one type a response renders

Core documents `relatedQuery` on every operation rendering resources of one type, keyed by that type's relations over one type that a read renders, so the bundle reads it on exactly those responses and checks every path against the rendered type. A related read filters its target only by its own `filter`, because a path names a relation of the target, not the target. A response rendering several types, a polymorphic related read or an action answering with mixed types, has no type to address, so every path on it is the same `400` an unknown path gets, as the profile requires of a path the server can't address. Responses rendering no resources, such as relationship reads, ignore the family. A create or update checks its query before it writes, so a refused query never answers `400` for a write that went through.

# The debug document route scan is cached against the route collection's resources

In debug, finding the route that serves each server's OpenAPI document meant loading the whole route collection on every request, which reloads every route file and costs hundreds of milliseconds. The scan now goes into a config cache file whose metadata is the collection's own resources, so it goes stale exactly when the router's matcher cache does: a route file changes, or the container is rebuilt, which the framework router tracks as a resource of the collection. Each file name carries a hash of the declared servers and the combined flag, so a configuration change never reads an older scan. Without the framework's config cache factory, or when the file can't be written, debug falls back to one scan per process, and outside debug the warmed result is read as before.

# A Doctrine rollback keeps managed what was managed before the transaction

ADR 0086 made every single write roll back through `DoctrineDataPersister::rollback()`, which cleared the whole `EntityManager`, so a failed write detached the security user and a Blameable-style listener handed it to the next flush as a new entity. The persister now notes, in `beginTransaction()`, the entities the unit of work manages and what each holds; `rollback()` keeps those managed, reloads one the transaction changed or that points at something rolled back, and detaches everything else, by clearing the unit of work and registering the kept entities again with their identity and original data. Detaching entity by entity was rejected because a detach cascades along `cascade: detach` mappings into kept entities and leaves the write's orphan removals and collection deletions scheduled, and an `onFlush` record was rejected because it misses changes the write never flushed; this replaces the clear in ADR 0086's first consequence, and the batched `each()` read lets go of its earlier batches the same way.

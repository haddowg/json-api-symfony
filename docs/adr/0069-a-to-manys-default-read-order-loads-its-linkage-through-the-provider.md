# A to-many's default read order loads its linkage through the provider

A to-many's default read order, its own `defaultSort()` else the related type's, has to hold on every read path, and the model's collection comes in whatever order the store returned it, so a relation with an order loads its linkage through the provider's batched related read even when the provider says it doesn't scope related reads, rather than reading the collection off the model and sorting it in PHP, which would load every member and could disagree with the store's collation and null ordering. The cost is one ordered query per relation across a page of parents, also in a write response; a relation with no order still reads off the model as before. A key only a pivot field answers is refused at warm-up when the related type's provider doesn't read pivot rows, because it would otherwise fail every read of the relation.
